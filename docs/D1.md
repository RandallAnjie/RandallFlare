# 去中心化 D1

每个 D1 数据库在创建时用 rendezvous hash 选定最多三个副本，副本组写入集群 KV 后保持
不变。SQL 写入先进入当前主节点的 Raft 日志，取得多数派确认后才在每个副本的 SQLite
事务中应用；读取由客户端自动跟随主节点。SQLite 文件中的 `_rf_applied` 标记和 Raft
持久日志共同避免节点在崩溃恢复时重复提交写入。

Worker 绑定实现 `prepare().bind().all()/first()/run()/raw()`、`exec()`、`batch()` 和
`withSession()`。单条查询最多返回 10,000 行、接受 1,000 个参数和 1 MiB SQL。
`batch()` 的 1 至 100 条语句现在作为一条 Raft 命令，在同一个 SQLite 事务内依次执行；
任何 prepare、约束或执行错误都会回滚整个批次。纯只读 batch 在主节点的同一读取事务中
执行，不会制造无意义的 Raft 日志。

## Schema 与数据概览

中文控制台会从主节点读取所有用户表（隐藏 `sqlite_*` 和 `_rf_applied`），显示建表语句、
列类型、主键、NOT NULL、默认值、总行数和最多 50 行样本。页面同时展示 `page_count`、
`page_size`、空闲页、WAL 模式和 `user_version`；所有表名都按 SQLite 标识符规则重新
引用，不能借 schema 名称注入额外 SQL。

## 导入 `.sql`

控制台接受最大 64 MiB、10,000 条语句的 SQLite 方言 SQL。文件会先完整解析和校验，
再按每 100 条组成一个原子批次提交。常见导出文件外层的 `BEGIN` / `COMMIT` / `END` /
`ROLLBACK` 包装会被移除，因为事务边界由每条复制的 batch 决定；其他语句保持原样。
已经成功的早期批次不会因后续批次失败而撤销，因此导入现有生产库前应先导出快照，或
先在新数据库中验证。

## 导出 `.sqlite`

导出请求可以发送给任意节点，客户端会跟随 D1 主节点。主节点使用 SQLite 在线 Backup
API 取得一致快照，在临时副本中移除 `_rf_applied`、切回 DELETE journal 并执行 VACUUM，
然后返回最多 200 MiB 的标准 SQLite 3 文件。下载结果可以直接用 `sqlite3`、DB Browser
或 Datasette 打开；临时文件无论成功失败都会清理。导出不会复制节点密钥、Raft 日志或
其他数据库。

## 备份到 R2 / rclone

手动备份不会先把文件下载到管理设备，而是由节点向当前 D1 主节点请求一致的在线
Backup 快照，并直接写入签名 R2 bucket：

```bash
rf d1 backup appdb --bucket backups --prefix d1-backups
```

控制台“迁移与快照”区域提供相同操作。快照 SHA-256、数据库名、创建时间和计划
时间写入 R2 custom metadata；超过单次 R2 直传上限时自动使用 multipart。目标
bucket 使用固定 rclone 或签名 rclone 分片策略时，备份无需任何额外适配。当前单个
D1 在线导出上限为 200 MiB。

自动计划属于全局签名存储策略，示例 JSON：

```json
[
  {
    "database": "appdb",
    "bucket": "backups",
    "prefix": "d1-backups",
    "interval_hours": 24,
    "retention_days": 30,
    "suspended": false
  }
]
```

可以在中文“底层存储”页面编辑，也可保存为 `d1-backups.json` 后签名发布：

```bash
rf storage configure \
  --new-bucket-backend local \
  --d1-backups-file ./d1-backups.json
```

策略不能引用不存在的数据库或 bucket；仍被任一备份策略引用的 bucket 不能删除。
每个时间槽由存活节点集合做 rendezvous 选举，只有一个节点主动执行；即便成员变化
造成短暂重复，确定性对象键也会安全覆盖同一计划快照。执行前会检查对象是否已经
存在，成功后按 R2 metadata 清理超过保留期的旧快照。

个人 API 令牌除了单条 `/query` 与 `/exec` 外，还可以调用
`POST /api/v1/d1/{database}/batch`，请求体为：

```json
{
  "statements": [
    { "sql": "INSERT INTO jobs (name) VALUES (?1)", "params": ["build"] },
    { "sql": "SELECT COUNT(*) AS n FROM jobs", "params": [] }
  ]
}
```

批处理写入要求 `d1:write`；`d1:read` 仍只允许单条只读查询。

CLI 提供相同的数据通路：

```bash
rf d1 batch appdb --file statements.json
rf d1 import appdb ./dump.sql
rf d1 export appdb --output ./appdb.sqlite
# 只有明确允许覆盖时才使用：
rf d1 export appdb --output ./appdb.sqlite --force
```
