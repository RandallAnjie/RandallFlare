# Worker 预览环境

RandallFlare 把静态 Pages 与脚本 Worker 统一为 Worker 项目，预览环境也沿用同一套
不可变清单、内容寻址 Blob、绑定与运行时。预览不是生产清单的下一版本，而是独立的
操作员签名资源；因此创建、续期和删除预览都不会改变生产流量。

## 历史版本预览

在项目详情的“预览”页选择任意未删除的历史版本和 1 至 90 天的保留期。版本 `v7` 的
项目 `api` 会得到确定性别名 `v7-api`，默认访问域名为：

```text
v7-api.<ingress.default_domain>
```

同一版本再次创建会续写该预览自己的签名版本链并更新到期时间。到期时间属于签名配置；
每个节点独立检查它，不依赖中央清理任务。删除会写入签名墓碑，节点随后停止路由和运行
实例，但审计历史仍然保留。

## GitHub Pull Request 预览

代码源配置中同时启用 GitHub Webhook 和“为 Pull Request 构建独立预览”，再让 GitHub
向控制台显示的回调地址发送 `push` 与 `pull_request` 两种事件。RandallFlare 只处理：

- `push`：生产分支，构建结果等待签名后发布到生产清单；
- `pull_request`：目标为生产分支的 `opened`、`reopened`、`synchronize`，固定获取
  `refs/pull/<编号>/head` 并校验最终检出的 40 位提交；
- 其他分支、动作和已删除分支：验证签名后安全忽略。

PR #42 的 `api` 项目使用 `pr42-api.<default_domain>`。每次同步更新同一预览资源，默认
保留 14 天；关闭 PR 后不再构建，最后一次签名版本自然到期，也可以在“预览”页提前删除。
Webhook 只能发起待审批资源，不能绕过操作员签名直接部署。

## 隔离与安全边界

- 预览使用独立运行时别名、端口、版本目录和 Durable Object 本地目录；不会接管生产
  DO 协调器，也不会收到生产 Cron 或 Queue 消费事件。
- 预览清单中的环境变量、加密 Secret 与平台绑定和该历史版本一致。预览代码因此可能访问
  项目原有的 KV、R2、D1、Queue 等数据；需要数据级隔离时，应给预览部署单独的绑定。
- 请求日志仍遵循隐私边界，只记录方法、路径、预览域名、状态、耗时、版本和节点，不记录
  查询参数、请求头、请求体、Cookie、IP 或 User-Agent。
- 内容块按需从对等节点修复；预览域名也进入 ACME 发现。生产环境建议为默认域配置 DNS
  通配符和通配符证书，避免每个预览单独签发。
