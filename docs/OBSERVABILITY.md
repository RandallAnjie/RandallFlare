# Worker 可观测性

RandallFlare 不建立中心日志服务。每个公开节点只保存自己实际处理的
Worker 请求；管理控制台通过现有的加密 Peer API 并行读取所有存活节点，
在浏览器返回前完成合并、排序和去重。节点离线不会阻塞其余数据，页面会
明确显示可用与暂不可用节点数量。

## 请求日志

每条记录只包含：

- Worker 名称与签名版本；
- 处理请求的节点 ID；
- 匹配的访问域名、HTTP 方法和不含查询参数的路径；
- 响应状态码、处理耗时和节点时间戳。

节点不会读取或保存查询参数、请求头、Cookie、Authorization、请求体、
客户端 IP 或 User-Agent。路径最长保留 2,048 字节，域名和方法也有固定
上限，避免无界基数占用内存。

入口线程只把记录加入有界内存队列。后台任务每秒批量写入本节点的 redb，
队列上限为 50,000 条；极端持续磁盘故障时会优先保留较新的记录，而不会
阻塞 Worker 响应。普通请求记录保留七天，每小时清理一次。

控制台“Worker → 日志”页面提供：

- 最近 24 小时的 2xx、3xx、4xx、5xx 分段趋势；
- 按访问域名和状态码类别筛选；
- 最近请求的节点、版本、路径、状态与耗时；
- 所有存活节点的 stdout、stderr 与系统运行日志。

24 小时聚合在各节点本地完成，控制台不会为了画趋势拉取七天原始记录。
节点间读取仍使用 RandallFlare Peer API 的 HMAC、目标节点绑定和
XChaCha20-Poly1305 请求/响应加密。

## 运维边界

redb 请求记录属于节点本地运行状态，不经 gossip 复制。这样既避免日志流量
反向淹没小型 VPS，也保持“节点只拥有自己观察到的数据”的去中心化边界。
若节点永久丢失，本节点尚未导出的日志也会随之丢失；需要更长归档时，应由
后续可选 Pipeline 导出任务写入普通 R2/rclone bucket，而不是让核心集群
依赖一个专用日志服务。
